# 03 · 像素渲染下的风格化植被

> English summary: for trees and bushes rendered at 64 texels/m with outlines, the canopy that worked is a set of
> "pads": domed clusters of thick scalloped leaves stacked like roof tiles, with per-layer shading in vertex colour, and
> cluster positions/sizes *measured* from the reference (or from an AI high-poly used only as a ruler). AI high-poly +
> decimation + texture transfer, assembling from generic elements, and fitting geometry directly to the high-poly surface
> were each tried for a day and rejected. Code lives in `01-blender-procedural-buildings/bkit` (`oak_pads.py`,
> `oak_trunk.py`, `veg.py`, `flat.py`); the finished oak is `examples/tree_oak.py`.

## 怎么看效果

- **只用游戏渲染器评估**（两档光、硬阴影、描边、64 texel/m、游戏机位）。Cycles 和网页预览器的效果都和游戏差很多。
- 给评审：参考图 + 改前 / 改后同机位并排，配三角形数、包围盒、剪影 IoU、树冠亮度分位数。
- 树的截图用白底，黑底看不清细节。

## 有效的做法

### 表面：纯色 + 顶点色明暗 + 浅几何

- 不用平铺贴图。每种材质一个纯色（参考图取中位色，sRGB → 线性）。
- 明暗写进顶点色（`flat.shade`）：朝下、被遮挡（半球射线）、凹沟（点属性 `puff_k`，1 = 鼓，0 = 沟）变暗，朝上稍亮。**每个网格都要有顶点色**
  （引擎侧也要保留 `COLOR_0` 并按线性 → sRGB 处理，否则顶点色被丢、纯色偏暗）。
- 质感交给浅几何：树皮沟、年轮环、板缝、草缕、圆角。

### 阔叶树冠：叶片叠成的团

评审一句话定了方向："花椰菜形状不是真的花椰菜，是叶子拼出来的。"

- 一团（`oak_pads.pad_cluster`）= 圆顶椭球 + 扇贝边厚叶片（厚 7 cm，7–10 个圆瓣）从顶往下分层叠成瓦片状，下沿外翘 14°；里面一个暗芯（叶色 × 0.45）挡缝。
- 层表 `(离顶角度°, 片数, 片半径/团半径)`：`(0,1,0.50) (34,6,0.40) (62,9,0.36) (90,11,0.32) (118,10,0.30)`，118° 那圈管团底。
- 每层明暗：每片叶 `puff_k` 中心 1，往边缘按 `(r/ρ)² × 0.8` 落，侧边 / 底面落到 0；`shade(w_crease=1.0, dark=(0.30,0.36,0.20), blur=0)`。
- **团的位置和大小照参考量，不用程序生成**：`PUFFS = [(E, S, U, 半径[, 竖向压扁])]`，橡树 11 团、半径 48–100 cm。
- 浅色厚橡叶 40 片搁在上面三层叶片中间，长 66 cm ± 15%。被上层压住一点边是对的，不查顶穿。
- 叶片底色要比参考图的树冠中间色亮（叠层遮挡多）：参考约 95/118/39，叶片底色 sRGB (0.54, 0.66, 0.14)。

### 树干

- 按参考图正面 / 侧面逐行量剪影半宽（`ENV` 表），底部外扩；根是同一根管子截面上的 7 个圆裂片，根头收成圆弧（不是一条条长尖根）。
- 树冠底下伸出两根粗主枝。

### 高模当尺子（之后的改进，评审："效果确实提升了"）

建法不变，只把"从参考四视图量"的团参数换成从 AI 高模量：用部件分割模型（P3-SAM）把高模拆成树冠部件 → 每块拟合压扁球
（拟合误差 / 半径 > 0.2 时改用包围盒内接椭球）→ 得到 `PUFFS`；高模树干中心对齐到原树干位置。半径缩放 1.0 胜过 0.85（"0.85 的位置有偏移了"）。

### 小植物别糊

64 texel/m 下，细叶片每片 1 px 宽、各自带描边，叠成暗杂线（"那几个小型植物好糊啊"）。像素渲染下最细特征要 ≥ 2–3 texel 才读得出：
用少而宽的叶片或叶团；交付时报最细特征的 texel 宽、描边像素占比、暗像素占比。

### 针叶树：按生长规律 + 叶簇卡 + 编辑器

叶片卡几轮被否（"好丑""明暗奇怪""叶子这么稀疏"）后定的路子：

1. 先研究这种植物怎么长，写成规则 + 参数表，再按 主干 → 主枝 → 侧枝 → 叶簇 建；叶簇大小跟着枝走（靠主干大、末梢小）。
2. 叶簇贴图不程序瞎画：生图模型照设计画单簇图集（白底）→ 抠图、每米 32 px、按长度分档、k-means 限色。
3. 明暗只留贴图自带那层，别再叠顶点色。
4. 做一个实时编辑器（引擎渲染、每个参数一个滑块、参数进地址栏），让评审自己调疏密大小。

这部分代码在游戏引擎里，未收录。

## 试过、被否掉的（别再走）

| 做法 | 结果 |
|---|---|
| 平铺贴图（64 texel/m + 最近邻） | "贴图很难看，没对齐的感觉" |
| 光滑叶团 + 少量小叶片 | "很丑"：小叶太小太少，树冠是光滑球 |
| 花椰菜小包 + 法线转移 | 法线转移把小包压平了 |
| 叶片卡 + 球形法线 | 三版"长得差不多"：只改了表面，结构没动 |
| 体素合成小花球 | 方向被纠正："是叶子拼出来的" |
| 叶簇分级 + 子团、叶片按绝对尺寸铺 | "团太多了"（37 团；参考约 8 个大团） |
| 空间殖民算法先长枝再挂叶 | "成团的感觉太弱"；往外推 / 贴轮廓后"越改越难看" |
| **AI 高模路线**（Hi3D 精修 100 万面 → 减面 → 上色） | 一整天后放弃："这种复杂的还是自己建模吧"，见下表 |
| 元素拼装（先建叶、花、果、蘑菇等元素再照参考拼） | "元素拼装的太丑了"：元素太规整、拼得松垮、颜色对不上 |
| 直接贴高模表面建（每团一个球帽 / 每团贴高模表面重网格） | "还不如我们自己建模的" |
| 风摆幅度大 | "怪怪的，幅度太大了"；默认 0.04 m 级，树干稳、树冠摆 |

### AI 高模路线的细节

| 环节 | 做法 | 结果 |
|---|---|---|
| 减面 | fast_simplification / pymeshlab / Blender Decimate | 位置误差都在底噪附近，但几厘米的小鼓包没了："劣化太严重" |
| 补细节 | 高模烘法线到低模 | 减面网格 UV 碎成几千块；评审觉得只要顶点色就够 |
| 上色 1 | 四视图投影取色 | 参考图带光照、和高模形状对不准："贴图效果很烂" |
| 上色 2 | Hunyuan3D-2.1 Paint | 正面还行背面差；官方代码只用第一张参考图（需打补丁才吃四张） |
| 上色 3 | Paint 贴图 → 顶点色 / 三色 / 纯色贴图 | 2 万顶点放不下叶形，"一大团一大团"；树皮判错、树干变绿 |

简单、块面大的东西（仙人掌这类）可以再评估 AI 路线；树和灌木走手工脚本。

## 资源占用（Hi3D v1.0 几何精修，RTX 5090 D）

1024 档：示例 14.8 GiB；植物 12.9–18.8 GiB，叶子多的（浆果灌木、蘑菇、苹果、秋枫、橡树、柳树）超 22 GiB 要 offload（约 450 s/样，峰值 11–12 GiB）。
1536 档必须 offload（约 937 s）。只出几何，固定减到 1M / 1M / 2M 面。

## 跑橡树示例

```bash
cd 01-blender-procedural-buildings
blender -b --factory-startup --python examples/tree_oak.py -- out/tree_oak.glb   # 约 7.6 万三角形，宽 4.9 × 深 4.1 × 高 4.5 m
```

环境变量（默认 = 定稿值）：`OAK_LEAF_SEED`、`SIZE_POW`、`MAINS`、`GROW`、`KIDS` 等，见脚本顶部。
