# 评估方法：怎么判断一个 3D 素材"变好了"

> English summary: report numbers, not impressions; judge in the renderer the game actually uses; ablate every
> conditioning input before tuning it; measure whole motions, not single frames; separate the reviewer from the builder;
> change one thing per round and keep the previous version side by side.

这些规矩是在几个月里被反复"打脸"之后定下的。每条后面写了是哪次教训。

## 1. 只报数，判断交给评审者

- 做的人对自己的结果有偏见：实测里"我看着变好了"和评审者的判断相反过很多次。交付时给**可核对的数**
  （三角形数、包围盒、剪影 IoU、色差、亮度分位数、关节角），外加并排图，好坏让评审者定。
- 数值全过 ≠ 对。IoU / 色差全过的模型照样可能"和参考图不像"；判据最终是"和挑中的参考图像不像"。
- 用户 / 评审者说"看着不对"就直接改，不拿现实尺寸、建筑规范去论证"其实是对的"（详见 `06-building-screen-proportions`）。
- 说法模糊时（"屋顶不够一整块"），把可能的症状列成多选让对方勾，不要自己猜一个去修。

## 2. 用目标渲染器评估

- 离线渲染（Blender Cycles：柔和阴影、光追遮挡）、网页预览器（三档卡通光、无阴影）和游戏引擎（两档光 + 硬阴影 + 描边 + 像素化）
  三者差别很大。曾经拿 Cycles 图调了一下午，评审者在游戏里看不出差别（"截图和模型的差别有点太大了吧"）。
- 对照图一律用游戏自己的渲染器出；Cycles 打光图只用来查穿模、漏光、接缝。
- 给评审者的主体是**可拖动的 3D**（原始 / 处理后 / 现有版并排），截图只是附加。百万面的页面不要默认自动旋转。

## 3. 条件输入会静默失效：先做消融

生成管线里的条件输入（参考图、姿态图、多视图）经常**不报错、能出图、结果还不错，但根本没进模型**。实际遇到过：

- 视频模型的姿态适配器里没有姿态权重：静止 / 倒序 / 正常三种姿态输入，输出逐像素相同。
- API 参数键名写错被静默丢弃，跑成了纯文生视频，还被夸"动作不错"。
- Hunyuan3D-2.1 Paint 传四张参考图，官方代码只用第一张（`input_images[0:1]`），贴图和单图版平均差 0.0。

做法：接上任何条件输入后，**第一件事是换一个完全不同的输入**，比输出差异，以"同输入重跑的差异"为标尺。
差 ≈ 0 = 没接上；差 ≥ 标尺若干倍 = 真在起作用。没做这个消融之前，关于该输入的任何调参结论都不成立。
另外：耗时突然变短要警惕（输入被丢后图完全相同，可能直接命中缓存）。

## 4. 指标会被"钻空子"：量整段，独立评审

- 角色挥工具动作只按"命中帧"量（工具头距目标、刃角、握点），优化方（无论是人还是 AI 代理）就把工具停在目标附近：
  数值全过，动作几乎没挥起来。**量整段**：预备最高点、挥动扫角、峰速、每个关键姿势的关节角、滑步、重心。
- 数值贴着阈值边（关节角差大量卡在 14–15°，阈值 15°）要当成可疑。
- 评审和建模分开：评审方不看建模方的推理过程，只看产物 + 测量。验收写成 rubric：判据 + 锚点 + 二元缺陷清单 +
  下限 / 上限，分数由代码算；测量结果可以否决视觉判断；每轮存档，最后取最好的一轮而不是最后一轮。

## 5. 改模型的纪律

- **一次只改一处**；改前改后同机位、同光照并排。7 个角度：正 / 右 / 背 / 左 + 俯视 + 斜 45° + 斜 225°（平视时贴图能盖住的浅凹凸，斜看一打光就显形）。
- 改之前先确认能**原样重建**（新旧 GLB 逐网格比对，`05-model-review-tools/glbeq.py`）；重构 / 抽库后也要回归。
- 每轮保留上一版；评审者说"越改越烂"就停，退回被认可的那版，不在坏版本上叠修。换路线后被说"不如之前"，立即退回。
- 问题优先在**源头**改（参考图、尺寸常量），不在产物上打补丁。
- 只修被点名的部位；不顺手改相邻结构（曾经顺手改了棕榈叶中脉，被否）。
- 所有问题记一张表：现象（引原话）→ 原因（带证据）→ 修法 → 状态 → **出在哪（模型本身 / 输入 / 自己的修改）**。
  实际统计里，一条"整体修形链"引入的问题比它修掉的还多（见 `02-multiview-image-to-3d`）。

## 6. 资源

- 大显存任务开跑前看已占用；按 `torch.cuda.max_memory_allocated` 记峰值（nvidia-smi 看到的是分配器总占用，偏大）。
  评估批次要分块：一次显存尖峰曾把 GPU 打掉线，只能重启。
- 几 GB 以上的权重，网络不稳时给直链手动下载，下完核对大小 / 哈希。

## 7. 可换装角色

- 每个装备都可能被摘掉：戴 / 不戴装备两套截图都要出（帽子下面没建头发，摘帽就是秃顶）。
- 被遮挡的部位用"遮挡槽位"隐藏，而不是干脆不建。
