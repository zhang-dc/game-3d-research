# 02 · AI 多视图图生 3D：四视图 → Pixal3D → 减面导出

> English summary: a 2×2 front/right/back/left sheet from one image-model call, reconstructed with Pixal3D (multi-view,
> pixel-aligned, ~1M faces with texture), then a visibility-culled decimation + rebake. Pixal3D's own export was the
> best result; every whole-model "fix-up" we added (solidify → voxel remesh → collapse → wall flattening → projection
> texturing) introduced more problems than it fixed. 33 failure modes are catalogued below with causes. For buildings we
> eventually switched to scripted Blender modelling (`01`), keeping AI reconstruction for irregular one-off props.

本节只收结论和一个独立小工具（`tools/roof_check.py`）。Pixal3D 的推理 / 导出脚本强依赖它的仓库内部模块和本机环境，没有收录。

## 流程（当时的主线）

```
一张 2×2 四视图（GPT Image 2.5，一次生成，切成 front/right/back/left）
 → 屋顶朝向闸门（roof_check.py；不过就重出，≤ 2 次）
 → 侧视图对称度 < 0.85 的单独重画（≤ 3 次）
 → （可选）四视图关键线拉齐：屋脊 / 檐口 / 石基 / 地面线、墙边，四张同高、左右对称，分段线性只挪位置
 → 按 Pixal3D 相机取景写 transforms.json（四张共用距离，第 0 帧必须是 front）
 → Pixal3D 多视图推理（--low_vram）→ 约 100 万面带贴图网格
 → 导出：剔除游戏视角看不见的面 → GPU 近似 QEM 粗减到目标 2.5× → MeshLab QEM 收尾 → 2× 超采样重烘颜色 + 法线贴图
 → 面数自动选：600 / 1200 / … / 5 万依次试，取第一个"8 视角平均破洞格子 ≤ 0.3%"的档
 → 比例闸门：3D 投影高宽比 vs 每张视图，偏差 > 15% 不过
```

实测（RTX 5090 D 32 GB）：每个模型 183–396 s；`--low_vram` 下 `max_memory_allocated` 16.4 GiB，但 nvidia-smi 看全卡在已有占用之上还要 23–25 GB；默认模式吃满 32 GB。

## 结论

1. **Pixal3D（多视图、像素对齐）明显好于单图 / 多视图的 Hunyuan3D-2 系列**：老虎窗这种小结构在后者里"都生成崩了"；剪影 IoU 正 + 侧合计 1.78–1.81 / 2，对比 2mv 正面 0.81–0.89。
2. **"它自带的减面导出"是基线，整体修形链全部否决。** 加厚 → 体素重建 → 塌缩 8000 面 → 压平墙面 → 四视图投影贴图，每一步都在丢模型本来做对的东西。
   问题表里 15 条是这条链自己引入的（下表"出在哪"一列）。之后的规矩：只按评审者点出的细节**局部**修，修前 / 修后 7 个角度对照。
3. **喂 3D 的参考图要单独生成**：简单体块、平涂、不描边、不像素化、没有杂物、均匀光照。给 2D 用的 ¾ 像素素材不能喂。
   - 像素画参考图会被建成台阶盒子，面数反而 5000–1 万。
   - 事后模糊 + 限色 + 中值滤波预处理被否（"一坨"）；**要什么画法就直接写进提示词**（"大块平面多边形、每面单色、无纹理"），短描述、不带参考图：5 棵树一次全过闸门，600–2500 面。
   - 提示词只给"是什么 + 风格句"，门窗材质比例交给生图模型；不要在提示词里写比例。
   - 只画静态结构（"no smoke, no fire, no sparks, no steam"）；会转的件（风车叶片）单独一项，塔身写 "without its sails"。
4. **一整张 2×2 比分开出四张一致得多**。但侧视图常被画成斜视（露半边屋面），四张之间也有 0.6 m 级的檐口高差 → 需要闸门和拉齐。
5. **像素对齐模型会把一面墙上的特征"印"到对面墙**：每张视图的特征沿视线投进体积，对称的房子分不清哪面是真的（空墙上长出对面的窗框、屋顶另一头长出烟囱鼓包）。
   但也可能四视图漏画、模型补对了——别默认当错（我们就把模型正确建出的两侧窗户当"印子"压平过）。
6. **透视 vs 正交**：Pixal3D 相机默认 20° FOV，四视图是近似正交立面画的 → 屋顶重建成轻微梯形。FOV 改到 10°（训练条件视图的下限）+ 拉齐，只在一栋上试过。
7. **薄件和成片细叶不适合**：草丛 / 芦苇 / 麦田破洞多、显存冲顶，改走 2D 精灵；圆灌木要写"几个大的实心叶簇"，否则只建出一层带缝的叶壳。
8. **减面别闭门造车，但形体路线没定之前调减面是白做。** GPU 近似 QEM 一次减太多会吃掉屋檐边、木梁、辐条这类薄件；MeshLab 一次减太多或开保边界会把厚墙内外两层压成一层（破洞 70%+）。
   颜色 MAE 测不出破洞，要按深度测屏幕破洞率。

### 被否 / 弃用 / 暂停

| 做法 | 结果 |
|---|---|
| 整体定型链（加厚 → 体素重建 → 塌缩 → 压平墙面 → 投影贴图） | 否决："你修过之后就拉完了" |
| 按尺寸重建（量四视图 → Blender 搭盒子 + 人字顶 → 投影贴图） | 否决："整个模型的细节都没了，直接一个平面" |
| 体素闭合"量化"成像素风 | 否决："一坨意义不明的东西" |
| 参考图事后预处理（模糊 + 限色） | 否决 |
| 模型自带的体素 to_glb 减面 | 弃用：2 万面破洞格子 13.7%、5 万 6.0% |
| 白模约束生图（白模多视图 → 生图 → 3D）、参数化白模 + 生图材质 | 停掉：太方正；直接出四视图更好 |
| Blender 光线投射重烘 / Smart UV + 重烘 / Decimate + 重烘 | 同一低模对 1784 万面高模：现流程 MAE 6.82；三者 7.31–9.04 |
| `gltfpack -si -sa` 事后压缩 | 跨 UV 接缝合并，贴图乱 |
| 拆件组装（屋顶 / 墙身 / 烟囱等各自生成再按框拼） | 暂停：屋顶表面坑洼、有切分痕迹；墙身单独喂时模型在空墙上"画出"花和窗的残影 |
| 换随机种子出多版挑 | 只在分件屋顶上试过：不同种子背面老虎窗长不长窗户都不同 |

### 减面方案调研（2026-10，调研完、未实测）

| 方案 | 做法 | 备注 |
|---|---|---|
| ComfyUI-UV-Decimate | 面数够时带 UV 的 QEM；少时焊点 → 减面 → xatlas 重展 → GPU 重烘 4 种贴图 | 专门针对 Pixal3D / TRELLIS 输出；指出 AI 模型 UV 碎成上千块、保留接缝会吃掉 63% 以上顶点预算；作者自测 1 个模型 |
| meshoptimizer | 可带 UV / 法线权重、宽松模式跨接缝、锁指定接缝、去碎块；`gltfpack -si` 直接吃 GLB | 业界用得广（three.js、Godot） |
| PaMO（PG 2025） | GPU：SDF + 对偶 MC 重建 → 并行 QEM 塌缩保证不自交 → 投回原表面 | 只管几何；论文报流形 / 不自交 100% |
| Simplifying Textured Triangle Meshes in the Wild（TOG 2025） | 处理非流形、碎块多的带贴图网格，不依赖原 UV | 没找到公开代码 |
| Robust Low-Poly Meshing（SIGGRAPH 2023） | 保特征的封闭偏移面 → 减面"流"回原模型 | 没找到代码 |
| 重拓扑（QuadriFlow / Instant Meshes / QuadWild / Quad Remesher） | 重生成四边面 | 更适合角色 |

建议的实测方法：同一个原始模型各出 2 万 / 8000 面两档，和现有导出放同一页 7 个角度并排，列面数、屏幕破洞率、用时。

更早的坑：

- 剔面时坐标轴按 Z 朝上写，模型输出是 +Y 朝上 → 把背面剔了。评测必须按视角拆开、含背面。
- trimesh 的 `apply_transform` / `scene.dump()` 按绕序重算顶点法线（这类网格 8.8% 面反向）；WebP 不传质量参数默认 q80，把法线贴图也压坏。
  法线贴图绿通道取反要配 glTF `normalScale.y = −1`。
- 长物体的侧视图伸进隔壁格子，2×2 切格时半截被切进来 → 切格后去掉不连通的串格。
- 宽度口径：`width_px` 必须是最长水平边，不是"左右宽"；否则长车被缩成高车。
- 3D 宽深比和四视图差 9–17%（车轮成椭圆）→ 按视图高宽比缩宽 / 深，不重生成。
- AI 网格是碎三角汤，硬减到 5k 面窟窿明显；压到 2k–9k 的预算要重拓扑 + 烘焙。

## tools/roof_check.py

四视图屋顶朝向一致性闸门，只依赖 numpy + Pillow。每张视图取剪影顶往下 12% 那行宽度 ÷ 最大宽度（先去掉烟囱这种宽度 < 8% 的细凸起）：
正 / 背差 ≤ 0.2、左 / 右差 ≤ 0.2，侧面平均比正背小 0.15 以上（屋脊沿正面走向）。

```bash
python tools/roof_check.py <四视图目录>...   # 目录里放 front/right/back/left.png（RGBA，透明背景）；退出码 = 不过的个数
```

在 61 张地区建筑四视图上只拦下 1 张（真有问题的那张）。
